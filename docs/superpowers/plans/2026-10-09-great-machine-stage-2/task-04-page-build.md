### Task 4: The skeleton of the page, and the build that embeds it

This task settles item 2 of the specification's section 15: gonixgo
builds a package that embeds a directory, from a source tree into which
another derivation's output was put. It was settled while this plan was
written, by doing what this task does; the check that closes it end to
end (the program Nix built answers `GET /` with the page) is in Task 5,
when `draal` has the flag that turns the page on.

**Files:**
- Create: `ui/go.mod`, `ui/package.json`, `ui/package-lock.json` (generated by `npm install`), `ui/tsconfig.json`, `ui/vite.config.ts`, `ui/index.html`, `ui/src/main.tsx`, `ui/src/App.tsx`
- Modify: `flake.nix` (Node in both shells, `packages.<system>.ui`, the source gonixgo builds)
- Modify: `.gitignore` (the page's dependencies and its build)
- Modify: `.envrc` (the sources of the page are watched)
- Modify: `.github/workflows/test.yml` (the steps `ui` and `test with the page`)

**Interfaces:**
- Consumes: from Task 1, the package `web` with `//go:embed all:dist` and the placeholder `web/dist/.gitkeep`, an empty file that git tracks; `web.Built() bool`. From the flake that exists: `goEnv.buildGoApplication` of gonixgo v0.2.0, the `version` string, `packages.<linux>.image`, the shells `default` and `bare`.
- Produces:
  - `ui/package.json` with the scripts `dev`, `check` (`tsc --noEmit`) and `build` (`vite build`, into `../web/dist`). The exact versions: `solid-js` 1.9.17, `@solidjs/router` 1.0.0, `@xterm/xterm` 6.0.0, `@xterm/addon-fit` 0.11.0, `vite` 8.3.4, `vite-plugin-solid` 2.11.14, `typescript` 7.0.2. Nothing else: a later task that needs another dependency adds it with its reason, and then follows Step 7 again for the hash.
  - `ui/vite.config.ts`: the build goes to `web/dist` (or to the directory `GREAT_MACHINE_UI_DIST` names, relative to `ui/`); before every build the directory is emptied but for `.gitkeep`, which is never away, not even after a build that failed; assets under `assets/` with a hash in their names, none of them inlined as a `data:` URI (the content security policy allows none); no source maps; target `es2022`. The dev server passes `/api`, WebSockets included, to `http://127.0.0.1:8080` with the `Host` the browser sent.
  - `ui/tsconfig.json`: strict; `jsx: preserve` with `jsxImportSource: solid-js`; it checks `ui/src` alone (`vite.config.ts` is not type checked: that would take `@types/node`).
  - `ui/src/main.tsx` renders `ui/src/App.tsx` into `#root` of `ui/index.html`. The tasks of the page replace `App.tsx` and build on the rest.
  - `packages.<system>.ui`: the build of the page, by `pkgs.buildNpmPackage` with Node 24 (`pkgs.nodejs_24`, 24.21.0 in the nixpkgs the flake pins). `packages.<system>.default` and the image are built from the repository with that build at `web/dist`.
  - Node 24 with `npm` in `devShells.default` and `devShells.bare`: `nix develop .#bare --command npm …` works, as `… go …` does.
  - CI: a step `ui` (`npm ci`, `npm run check`, `npm run build`, and git sees no change) after `sqlc`, and a step `test with the page` after it.

What this costs at evaluation, which the README says in Task 11: gonixgo
asks `go list` during evaluation which files `web` embeds, so the source
with the page in it has to exist then. Nix builds it during evaluation
(import from derivation, which gonixgo needs already for its own tool):
the page whenever something in `ui/` changed (about 25 seconds the first
time, for the dependencies; 5 to 10 after that), and a copy of the
repository whenever any tracked file changed (a second). Both are built
on the machine that evaluates, by its own nixpkgs, as gonixgo's resolver
is. An `npmDepsHash` that is stale therefore fails every command that
evaluates the program, the default shell among them, and not `nix build
.#ui` alone; the bare shell still opens.

- [ ] **Step 1: Node in the shells, and the page in the flake**

Replace `flake.nix` with this. Against the file that is there: the
functions `nodejs` and `ui` are new, `evalPkgs` got a name, `src` is new
and is what `buildGoApplication` takes instead of `./.`, `packages` has
`ui`, and both shells have Node. `npmDepsHash` is a hash that is wrong on
purpose: the right one cannot be known before Step 3 has made the lock
file, and Step 7 puts it in.

```nix
{
  description = "great-machine";
  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixos-26.05";

    systems.url = "github:nix-systems/default";

    gonixgo = {
      url = "github:draganm/gonixgo/v0.2.0";
      inputs.nixpkgs.follows = "nixpkgs";
      inputs.systems.follows = "systems";
    };

  };

  outputs = { self, nixpkgs, systems, gonixgo, ... }@inputs:
    let
      eachSystem = f:
        nixpkgs.lib.genAttrs (import systems)
        (system: f system nixpkgs.legacyPackages.${system});

      # What `great-machine version` prints. A release is built with the
      # tag in GREAT_MACHINE_VERSION and --impure, without which Nix reads
      # no environment; every other build is named by its commit, with
      # -dirty when the tree had changes.
      version = let fromEnv = builtins.getEnv "GREAT_MACHINE_VERSION";
      in if fromEnv != "" then
        fromEnv
      else
        self.shortRev or self.dirtyShortRev or "dev";

      # The Node that builds the page, in the derivation and in the
      # shells: the same one, so that `npm ci` in a shell and the
      # derivation read package-lock.json alike.
      nodejs = pkgs: pkgs.nodejs_24;

      # The page: ui/ built by Vite. Its output is what web/dist holds
      # after `npm run build`: index.html, assets/ and the placeholder.
      #
      # npmDepsHash is the hash of the dependencies package-lock.json
      # names. After any change of ui/package-lock.json:
      #   nix run nixpkgs#prefetch-npm-deps ui/package-lock.json
      # prints the new one. With a stale hash the build fails and names
      # the right one in its "got:" line.
      ui = pkgs:
        pkgs.buildNpmPackage {
          pname = "great-machine-ui";
          version = "0";
          src = ./ui;
          nodejs = nodejs pkgs;
          npmDepsHash = pkgs.lib.fakeHash;
          # vite.config.ts writes the build here instead of ../web/dist,
          # which is outside what a derivation may write.
          env.GREAT_MACHINE_UI_DIST = "dist";
          installPhase = ''
            runHook preInstall
            cp -r dist $out
            runHook postInstall
          '';
        };
    in {

      # Evaluating a gonixgo package runs `gonixgo resolve` through
      # builtins.exec, so every command that touches `packages` needs
      #   --option allow-unsafe-native-code-during-evaluation true
      packages = eachSystem (system: pkgs:
        let
          # This pkgs builds gonixgo's own tool and the Go program.
          #
          # The resolver runs on the machine that evaluates. That is this
          # system, unless a package of another system is asked for, as
          # the Linux image is on a Mac: then --impure tells which machine
          # evaluates, and its nixpkgs runs the resolver.
          evalPkgs = if builtins ? currentSystem && builtins.currentSystem
          != system then
            nixpkgs.legacyPackages.${builtins.currentSystem}
          else
            null;
          goEnv = gonixgo.lib.mkGoEnv { inherit pkgs evalPkgs; };

          # The source gonixgo builds: the repository with the build of
          # the page at web/dist, where the package web embeds it.
          #
          # gonixgo asks `go list` while Nix evaluates which files a
          # package embeds, so this source has to exist then: Nix builds
          # it, and the page before it, during evaluation, on the machine
          # that evaluates. That is why both come from that machine's
          # nixpkgs. The files of the page are the same wherever they are
          # built, and gonixgo copies the files of each package out of
          # this source, so the derivations of the program do not depend
          # on what machine evaluated them.
          src = let
            p = if evalPkgs != null then evalPkgs else pkgs;
            page = ui p;
          in p.runCommand "great-machine-src" { } ''
            cp -r ${./.} $out
            chmod -R u+w $out
            cp -r ${page}/. $out/web/dist/
          '';

          # The one program: draal, zathras and the operator's commands.
          # Without cgo it is linked statically on Linux, and runs in an
          # image that has no libc and whose /nix/store is another one.
          great-machine = goEnv.buildGoApplication {
            pname = "great-machine";
            inherit src;
            subPackages = [ "cmd/great-machine" ];
            CGO_ENABLED = 0;
            ldflags = [
              "-X github.com/fables-for-robots/great-machine/cli.Version=${version}"
            ];
            meta.license = pkgs.lib.licenses.lgpl3Only;
          };

          busybox = pkgs.pkgsStatic.busybox;
        in {
          default = great-machine;
          ui = ui pkgs;
        } // nixpkgs.lib.optionalAttrs pkgs.stdenv.hostPlatform.isLinux {
          # The image of the app container of a pod, and of draal:
          #   nix build .#image && docker load < result
          #
          # Nothing it needs lives in /nix/store, because a pod mounts the
          # sidecar's store there: the program, busybox and the
          # certificates are copied to where an image has them. That
          # works because all three are files that need no other.
          image = pkgs.dockerTools.buildLayeredImage {
            name = "ghcr.io/fables-for-robots/great-machine";
            tag = "nix";
            extraCommands = ''
              mkdir -p bin etc/ssl/certs root
              mkdir -m 1777 tmp

              cp ${great-machine}/bin/great-machine bin/great-machine

              # busybox is /bin/sh and the tools of a shell session.
              cp ${busybox}/bin/busybox bin/busybox
              for tool in $(bin/busybox --list); do
                [ -e "bin/$tool" ] || ln -s busybox "bin/$tool"
              done

              # iroh's relays are reached over HTTPS.
              cp ${pkgs.cacert}/etc/ssl/certs/ca-bundle.crt etc/ssl/certs/ca-certificates.crt

              echo 'root:x:0:0:root:/root:/bin/sh' > etc/passwd
              echo 'root:x:0:' > etc/group
            '';
            config = {
              Entrypoint = [ "great-machine" ];
              Env = [
                "PATH=/bin"
                "HOME=/root"
                "SSL_CERT_FILE=/etc/ssl/certs/ca-certificates.crt"
              ];
            };
          };
        });

      # The shell carries the built program, so entering it (or direnv
      # reloading it after a source change, see .envrc) rebuilds it. It
      # therefore needs the same evaluation option as `packages`.
      devShells = eachSystem (system: pkgs: {
        default = pkgs.mkShell {
          hardeningDisable = [ "all" ];

          packages = with pkgs; [
            go
            sqlc
            (nodejs pkgs)
            self.packages.${system}.default
          ];
        };

        # The same tools without the built program and the built page. The default shell
        # cannot be entered while the module does not resolve, for example
        # after a `go get` that left go.sum behind; this one can, to run
        # `go mod tidy`. It needs no evaluation option.
        bare = pkgs.mkShell {
          hardeningDisable = [ "all" ];

          packages = with pkgs; [ go sqlc (nodejs pkgs) ];
        };
      });
    };
}
```

`ui/vite.config.ts`:

```ts
import { mkdirSync, readdirSync, rmSync, writeFileSync } from "node:fs";
import { join, resolve } from "node:path";
import { defineConfig, type Plugin } from "vite";
import solid from "vite-plugin-solid";

// Where the build goes: web/dist, which the Go package web embeds. The
// Nix derivation of the page sets GREAT_MACHINE_UI_DIST, as it may not
// write beside its source.
const dist = resolve(import.meta.dirname, process.env.GREAT_MACHINE_UI_DIST || "../web/dist");

// The placeholder that git tracks in web/dist, without which go:embed
// would have no directory to embed before the first build.
const placeholder = ".gitkeep";

// cleanDist empties the directory of the build before a build, but for
// the placeholder. Vite's own emptyOutDir would delete the placeholder
// too, and a build that then failed would leave the Go module unable to
// compile.
function cleanDist(): Plugin {
  return {
    name: "great-machine:clean-dist",
    apply: "build",
    buildStart() {
      mkdirSync(dist, { recursive: true });
      for (const name of readdirSync(dist)) {
        if (name !== placeholder) {
          rmSync(join(dist, name), { recursive: true, force: true });
        }
      }
      writeFileSync(join(dist, placeholder), "");
    },
  };
}

export default defineConfig({
  plugins: [solid(), cleanDist()],
  build: {
    outDir: dist,
    // cleanDist does it, and keeps the placeholder.
    emptyOutDir: false,
    assetsDir: "assets",
    // No file is put into another as a data: URI: the content security
    // policy of the page allows its own origin alone, and data: is none.
    assetsInlineLimit: 0,
    sourcemap: false,
    target: "es2022",
  },
  server: {
    // draal, or `go run ./web/demo`, on its default address. A request is
    // passed on with the Host it came with (no changeOrigin): the API
    // refuses a WebSocket whose Origin is not its Host, and the Origin a
    // browser sends is this server.
    proxy: {
      "/api": { target: "http://127.0.0.1:8080", ws: true },
    },
  },
});
```

`ui/src/App.tsx`:

```tsx
import { createSignal, onCleanup, onMount, Show } from "solid-js";

// The skeleton of the page: its name and, as a first sign of life, the
// number of services in the first message of /api/watch.
export default function App() {
  const [services, setServices] = createSignal<number>();
  const [failed, setFailed] = createSignal(false);

  onMount(() => {
    const scheme = location.protocol === "https:" ? "wss:" : "ws:";
    const socket = new WebSocket(`${scheme}//${location.host}/api/watch`);
    socket.onmessage = (event) => {
      if (typeof event.data !== "string") {
        return;
      }
      const fleet: unknown = JSON.parse(event.data);
      if (typeof fleet === "object" && fleet !== null && "services" in fleet) {
        const list = fleet.services;
        setServices(Array.isArray(list) ? list.length : 0);
        setFailed(false);
      }
    };
    socket.onerror = () => setFailed(true);
    socket.onclose = () => {
      if (services() === undefined) {
        setFailed(true);
      }
    };
    onCleanup(() => socket.close());
  });

  return (
    <main>
      <h1>great-machine</h1>
      <Show
        when={services() !== undefined}
        fallback={<p>{failed() ? "draal does not answer." : "Asking draal…"}</p>}
      >
        <p>services: {services()}</p>
      </Show>
    </main>
  );
}

Against the file that is there: the comment of `defaults` names Node, the steps `ui` and `test with the page` are new, and the comment above `nix build` says where its page comes from. `go test ./...` stays before the page is built, on purpose: that the Go module builds and passes without the page is a constraint of this plan, and this is the step that holds it; the packages that serve the page then run a second time with it.

```yaml
name: Test

on: [push, pull_request]

permissions:
  contents: read

jobs:
  test:
    runs-on: ubuntu-latest
    # Every `run` step runs in the flake's bare shell, which has the Go,
    # the sqlc and the Node that the dev shell has. A step added here
    # needs no setup of its own for them.
    defaults:
      run:
        shell: nix develop .#bare --command bash -e {0}
    steps:
      - uses: actions/checkout@v4
      - uses: cachix/install-nix-action@v31
      - uses: actions/cache@v4
        with:
          path: |
            ~/go/pkg/mod
            ~/.cache/go-build
          key: go-${{ runner.os }}-${{ hashFiles('go.sum', 'flake.lock') }}
          restore-keys: go-${{ runner.os }}-
      - name: gofmt
        run: test -z "$(gofmt -l .)"
      - name: vet
        run: go vet ./...
      - name: test
        run: go test ./...
      # db/dbq is what sqlc makes of db/queries and db/migrations, and
      # nothing else: a query that was changed without `go generate ./db`
      # fails here.
      - name: sqlc
        run: sqlc diff
      # The page: its dependencies as package-lock.json names them, the
      # type check, and the build into web/dist. A build leaves nothing
      # that git sees: web/dist is ignored but for its placeholder, which
      # the build keeps.
      - name: ui
        run: |
          cd ui
          npm ci
          npm run check
          npm run build
          test -z "$(git status --porcelain)"
      # `test` above ran without the page, as the Go module has to build
      # and pass without it. The packages that serve the page run once
      # more now that web/dist holds it.
      - name: test with the page
        run: go test -count=1 ./web/... ./cli/ ./e2e/
      - name: pid1
        run: scripts/test-pid1.sh
      # Steps that test more are added above this line. The last steps
      # build the program as a release does: Nix builds the page by
      # itself and puts it into the program, whatever the steps above
      # left in web/dist, which git ignores and Nix therefore does not
      # see. gonixgo runs a program while Nix evaluates, which Nix allows
      # only when asked.
      - name: nix build
        run: |
          nix build --option allow-unsafe-native-code-during-evaluation true
          ./result/bin/great-machine version
      # The image as a release builds it, and what a pod asks of it: that
      # it runs with another store mounted over /nix/store.
      - name: image
        run: |
          nix build .#image --option allow-unsafe-native-code-during-evaluation true
          docker load < result
          docker run --rm --tmpfs /nix/store ghcr.io/fables-for-robots/great-machine:nix version
          docker run --rm --tmpfs /nix/store --entrypoint sh ghcr.io/fables-for-robots/great-machine:nix \
            -c 'test -d /tmp && test -s /etc/ssl/certs/ca-certificates.crt'
```
